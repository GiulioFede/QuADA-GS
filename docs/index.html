State-of-the-art Gaussian Splatting methods for arbitrary-scale super-resolution usually give every pixel the same number of Gaussians. They lack an adaptive densification mechanism that would spend few Gaussians on low-frequency regions and many on areas of high detail. QuADA-GS predicts, from the low-resolution input alone, where detail actually lives and spends Gaussians only there. This cuts memory and inference cost and delivers a state-of-the-art quality–cost trade-off.

Abstract

Arbitrary-Scale Super-Resolution (ASR) aims to reconstruct high-resolution images at any continuous magnification. While 2D Gaussian Splatting (GS) has recently shown great promise for ASR, current methods struggle to balance visual quality and computational cost. Approaches targeting high fidelity rely on powerful backbones and uniform, highly dense Gaussian grids, leading to prohibitive memory and inference costs. Conversely, methods prioritizing efficiency aggressively simplify their architectures, severely compromising visual quality.

To bridge this gap, we observe that a core capability of GS remains largely underexplored in ASR: the potential for dynamic densification, i.e., the spatially adaptive allocation of Gaussians based on image content. Unlike standard scene fitting, where densification is guided by a known ground truth, applying this to ASR is highly non-trivial because the high-resolution target is exactly what the model must predict.

To address this challenge, we propose QuADA-GS, an approach that retains a powerful representational backbone but autonomously predicts where to allocate Gaussians relying strictly on the low-resolution input. By adopting a sparse approach, QuADA-GS refines features and increases Gaussian density strictly where structural complexity demands it. Because this adaptive allocation produces a non-uniform hierarchical topology, we introduce a novel, highly efficient communication mechanism to process these sparse features, bypassing standard dense bottlenecks. Extensive experiments indicate that our approach successfully balances visual quality and computational requirements, providing an improved and competitive trade-off for ASR.

Method

Four steps replace the dense upsampling of GSASR.

The backbone is kept at full strength, exactly as in GSASR: an off-the-shelf extractor (EDSR-baseline or RDN) followed by a scale-conditioned window-attention refiner produces a feature map Fbase of size C×H×W. Trimming this stage would irreversibly cap the detail that can be recovered, so savings come from what happens after it.

  1. Predict how much detail each feature needs

    A lightweight, parameter-free structure tensor measures local content on the ground-truth image: near-zero eigenvalues mean flat, one dominant eigenvalue means an edge, two comparable ones mean texture. They are combined into a per-pixel score, using weights [3, 1] found by ablation:

    score = max(0, wtexture λ2 + wedge (λ1 − λ2))

    The score map is resized to the feature grid and cut at two thresholds, φ1 < φ2, into the Structure Map: level 0 (×1, flat), level 1 (×2, edges and structure), level 2 (×4, complex texture). At inference no ground truth exists, so a small CNN head regresses the score map directly from Fbase, trained with an ℓ2 loss. Drag the thresholds in the demo above to see the allocation change.

  2. Split features independently

    Flat (×1) features are set aside. The rest go through a shared ×2 expansion in which a small MLP splits each feature into four children. Features assigned ×2 are now complete; those assigned ×4 are split once more. Each feature expands on its own, so the work parallelizes, and the output is a sparse quadtree: 1 Gaussian per flat feature, 4 per edge feature, 16 per texture feature, against 16 everywhere in the dense baseline.

    Because every child is produced without seeing its siblings or neighbors, they are blind to one another. The next step restores that.

  3. Let neighbors talk, in O(1)

    After a split, neighbors can sit at different depths and have different sizes, so a regular convolution grid no longer applies. Generic sparse indices do not fit either: hash tables collide and a single feed-forward pass cannot repair them, 1D orderings such as Z-curves place adjacent regions far apart, and tree traversals take a variable number of steps that stall GPU threads.

    But our quadtree splits are perfectly predictable, so a child’s address is known in closed form. Each feature writes its id into a dense 2D index, the Pointer Grid P (4H×4W), over the region it owns. A feature of side S at (x0, y0) then reads nine neighbors straight from P:

    O(S) = {−1, ⌊S/2⌋, S}    Nm = { P[y0+dy, x0+dx] : dy, dx ∈ O(S) }

    A standard 3×3 convolution over those nine features updates the feature residually. This is the Hierarchical Pointer Convolution (HPC). Search time stays flat at about 0.47 ms from ×2 to ×8. Try it below.

    Hover or tap any cell of the grid.

    Nine array reads, no hashing, no tree walk, no sorting. Dashed circles fall outside the image.

  4. Decode and rasterize

    Each final feature owns a region of side S ∈ {1, 2, 4}. An MLP decodes it into a continuous 2D Gaussian: opacity, color, correlation, a center offset, and two scales. The scales are multiplied by S, so fine features give compact Gaussians and coarse ones cover the wide area they were decoded from. With the GSASR CUDA rasterizer, the image at any scale s is a sum over all N Gaussians:

    ISR(x, y; s) = ∑i=1N Gi(x/s, y/s)

Cost: where the Gaussians go

In the example below, a 512×512 input upscaled ×4, GSASR needs over 4.2M Gaussians, 45K of them allocated to flat areas where only 6.6K are active. QuADA-GS lands within 0.08 dB PSNR of it with 502K Gaussians, runs 5× faster and uses 3.7× less memory. It is 2.3× faster than ContinuousSR with half the memory and 0.06 dB higher PSNR. Against GaussianSR it is 23× faster and 6× lighter, while GaussianSR keeps a 0.14 dB PSNR lead.

Where it gives ground, and what ULTRA shows

On Urban100, QuADA-GS has the best PSNR from ×3 to ×12 and the best SSIM at every scale, while GSASR and ContinuousSR* lead LPIPS and DISTS. On Set14, GSASR leads PSNR from ×3 to ×8. Fewer, larger Gaussians in flat regions slightly lower PSNR. PSNR is a pixel-wise error that weights every pixel equally, so tiny, perceptually negligible errors across vast flat areas add up. To test this explanation we trained ULTRA, which quadruples flat-region density by upsampling Fbase to 2H×2W before the same sparse pipeline, for a virtual 8H×8W resolution. Compared with the base model, ULTRA improves on 71 of the 72 combinations of metric, scale and dataset in the paper’s tables (four metrics, six scales, two datasets); the remaining one, DISTS at ×4 on Urban100, is a tie. The extra detail is visible.

A dense method would pay dearly to reach that resolution. Against a dense baseline at the same 8H×8W, ULTRA needs about 61% less inference time and about 35% less memory (Supplementary Material).

Code

Inference and evaluation code (PSNR, SSIM, LPIPS, DISTS, with runtime and memory profiling) are public. The recommended pretrained model, RDN_best, downloads automatically from the repository’s releases the first time you run the script.

Install
git clone https://github.com/GiulioFede/QuADA-GS.git
cd QuADA-GS

# PyTorch for your system (we use CUDA 12.4)
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu124
pip install -r requirements.txt

# custom CUDA rasterizer
cd utils/gs_utils
python setup_gscuda_adaptive.py install
Super-resolve a folder
python inference/evaluate_inference.py \
    --path_to_image_dataset "/path/to/low_res_images" \
    --results-dir "/path/to/output" \
    --pretrained_model "RDN_best" \
    --scale_to_evaluate 12 \
    --dmax 0.1 0.1 0.1
Compute metrics against ground truth
python inference/compute_metrics.py \
    --sr-dir /path/to/output \
    --gt-dir /path/to/ground_truth

Pretrained models

RDN_bestRecommended. The official model from the paper: RDN encoder, after the full ablation and level-cost tuning.
RDN_classicRDN encoder with the classic level cost (0.0625, 0.25, 1.0), giving a strongly quadtree-like topology. Weights to be released.
EDSREDSR encoder, for a backbone comparison. Weights to be released.

For very small inputs (for example 32×24) or extreme scales, raise --dmax for all levels. It trades a little speed for structural continuity and avoids gaps in the output.
